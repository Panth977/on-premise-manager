Prototype build plan

Build a working prototype in one day. It must run one full cycle end to end: import an image, create a deployment from a template, install agents on 2 servers, approve the first setup, change a value, publish, and roll back.

Goal

Status and activities must show in both GUIs at every step.

    Test plan

    Setup

    • 2 Linux VMs (Ubuntu 24.04, 2 vCPU, 4 GB) on one network: app = 10.0.1.10, db = 10.0.1.11
    • Docker Engine: nothing to do (the install script installs the pinned Docker 28.5.2 when it is missing; an existing Docker 20.10 or newer is used)
    • Ports 80/443 (edge), 8080 (GUI alias) and 7080 (mesh) open between the VMs and from your laptop
    • No other program on ports 80/443 of the VMs (the agent edge binds them)
    • Outbound 443 to the API domain

    Commands to check

    systemctl status opm-agent
journalctl -u opm-agent -n 50
docker ps --filter label=opm.deployment
curl -s http://10.0.1.10/_opm/healthz
curl -s http://10.0.1.11/_opm/healthz
curl -s -o /dev/null -w "%{http_code}" \
  http://10.0.1.10/no-such-path   # 404 page
    1. InstallRun the install command on each VM. Check that both agents show in the cloud Status page.
    2. First setupApprove the first proposal. Check that postgres on db is ready before api on app starts.
    3. FailurePublish a proposal with a bad health check. Check that both sites roll back and the proposal shows failed-rolled-back.
    4. Local changeChange an env value in the agent GUI. Check that the cloud Diff page shows the new head.
    5. Stale proposalPublish from an old draft after a local change. Check that the agents mark it stale.
    6. RollbackRoll back to the pre-update snapshot. Check the site volumes (restored by volumeSlug) and the head.
