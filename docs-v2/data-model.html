This page defines every stored type of On-Prem Manager (OPM). Each type has a TypeScript block, a field table, a valid JSON example, and the validation rules. If a field is not on this page, it does not exist.

How to read this page
  • The TypeScript blocks are the contract. JSON on the wire uses the same names.
  • Mutable tells you who can change a field after create: never, cloud (cloud frontend / API), agent (local proposal in the agent GUI), or system (set by OPM itself).
  • A service has one identifier: its serviceSlug (for example web, api, postgres). There is no serviceId. An image has one identifier in its service: its version (for example v1).
One identifier per entity

Each entity has exactly one identifier. The identifier is the document id. It never changes after create. Do not add a second id field to an entity.

A container is one instance of an image on a site. It refers to its image with serviceSlug + version, and has its own name containerSlug. The same image can run many times on one site, each time with its own env, ports and volumes (for example worker and worker-2 with a different NODE_ENV). Data folders are declared once on the site (SiteConfig.volumes, see SiteVolume); a container mounts one by its volumeSlug, and several containers may share one. On a site, the agent tags the loaded image <serviceSlug>:<version>, for example northwind-backend:v1. Every instance of that version uses the same tag.
