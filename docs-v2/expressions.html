Expressions

An expression is a {{ … }} block inside a string value or inside a text file. It lets one value depend on a variable, a secret, a file, another container or another site. The agent resolves expressions on the site. The cloud stores them as raw text.

Where OPM resolves expressions

Fields that accept expressions

Only fields of type Value, the two number fields below, and the content of text files with render: "expressions" accept expressions. All other fields take literal values only (for example commands, slugs, agentPort, agentGuiAliasPort, edge ports, route path prefixes, TLS modes).

No secrets in the edge

secret.* is E_NOT_ALLOWED in every edge field. The edge config is written to /var/lib/opm/edge/caddy.json and shown in the GUI, so it must not hold secret values. TLS keys and DNS tokens are named by slug (keySecretSlug, dnsTokenSecretSlug); the agent passes them to Caddy in memory. Edge expressions resolve at staging, like hosts; a route never changes per request except the single-brace placeholders.

Required variables are set at deployment

A template does not know the values of a deployment. Mark such a variable Required and leave its value empty. In a template this is normal: there is no warning. Every preview that uses it shows the token ‹set at deployment› (a dashed chip). Checks that need the real value (host format, mount path, options, JSON, numbers) wait for the value. In a deployment draft the variable shows one warning, "… is required — set it before publishing", and publish is blocked until it has a value. The sites never see an empty required value. An optional variable without a value gives one note (V_VAR_OPTIONAL_NULL, severity info, not a warning) in a template: add | default(…) where it is used, or a template default. Required secrets work the same way.

Optional site host (auto)

SiteConfig.host is optional. Leave it on Auto-detect (the default, null) when you do not know the address of the machine before the install. The agent reports its addresses at enroll and in every heartbeat (detectedAddresses) and the site uses its advertised address. In the cloud, a site that is not installed yet shows <auto:siteSlug> ("auto · detected on install") in previews; that placeholder is never sent to a site. On a site, an auto host that has not been reported yet gives E_NULL when another value uses site.<s>.host or self.host. A host such as {{ var.server-ip }} whose variable has no value does not block: the site uses its auto address and the cloud shows the warning V_HOST_AUTO "var server-ip has no value — leave host on auto or set the variable".

Why host and ports are limited

Site hosts and ports are inputs of site.* paths. If a host could use site.*, two sites could refer to each other in a loop. So host and port expressions can use var.* and deployment.id only.

Grammar (EBNF)

template   = { text | block } ;
text       = any characters, except the two characters "{{" ;   (* line breaks are allowed in file content *)
block      = "{{" , ws , expr , ws , "}}" ;
expr       = primary , { ws , "|" , ws , filter } ;
primary    = path | string | number | boolean ;
path       = root , "." , segment , { "." , segment } ;
root       = "var" | "secret" | "file" | "site" | "self" | "deployment" | "container" ;
segment    = ( letter | digit ) , { letter | digit | "-" | "_" } ;   (* slugs and document ids *)
filter     = name , [ "(" , ws , [ arg , { ws , "," , ws , arg } ] , ws , ")" ] ;
name       = "default" | "join" | "upper" | "lower" | "trim" | "base64" | "url" | "int" | "json"
           | "sha256" | "sha512" | "mosquitto_passwd" ;   (* lexed as [a-z] { [a-z0-9_] } *)
arg        = string | number | boolean ;
string     = '"' , { char - ( '"' | "\" ) | "\" , ( '"' | "\" ) } , '"' ;
number     = [ "-" ] , digit , { digit } , [ "." , digit , { digit } ] ;
boolean    = "true" | "false" ;
ws         = { " " | "\t" } ;
  • A string can hold {{ and }}. The parser ignores them inside a string literal.
  • A block cannot span lines.
  • Escape: to write a literal {{ in a value or a file, use the block {{ "{{" }}. A literal }} outside a block needs no escape. There is no other escape syntax; files use the same grammar.

Expressions in files

A text file (FileDef.editor = "text") has render: "expressions" by default (toggle Resolve {{ }} expressions in the file form). Its content is then a template. Binary files are never rendered. On the site, at staging, the agent renders the file once for the site: each site keeps ONE copy at the file's location (auto = <agentHome>/files/<fileSlug>, or a custom ./… / absolute path set on the Files page), and every container that mounts the file bind-mounts that single host file read-only. So a file cannot use container.* or file.* (E_NOT_ALLOWED: "files are shared by all containers on the site — use a variable instead"). Something that must differ per container belongs in an env var or a variable. The agent writes a staged copy next to the location and swaps it in atomically at apply. The stored content in the cloud stays the source text.

{
  "site": "{{ self.slug }}",
  "logLevel": "{{ var.log-level }}",
  "api": "http://{{ site.app.host }}:{{ site.app.port.api.http }}",
  "dbPassword": "{{ secret.db-password }}",
  "template": "{{ "{{" }} user.name }}"
}

On the site app this renders "site": "app" and "template": "{{ user.name }}" (the escape writes a literal {{). Because it uses a secret, the copy is written with mode 0400; a file without secrets gets 0444.

  • Secrets are allowed in files. The rendered bytes never go to logs, activities, .opmlog bundles or snapshots; a snapshot restore renders again.
  • A block that does not resolve fails the staging with V_FILE_RENDER: "<fileSlug>:<line>:<col>: <code> <message> (site S)" (once per site).
  • A file with a JSON mime (application/json or *+json) must render to valid JSON, else V_FILE_JSON.
  • The cloud file editor highlights blocks, completes paths, checks the source while you type (line:col), and Preview for site… shows the rendered file for a site you pick, with secrets as •••.
  • A file that must hold literal {{ }} (a Handlebars or Go template, for example) either uses the escape or turns rendering off (render: "none"). The TLS certificate file of the edge is never rendered.

Reach another container of the same site

Use the plural root containers.<containerSlug>. It gives the DNS name and the internal port of any container of this site (also this container). For example, the backend reaches the MQTT broker like this:

MQTT_URL = mqtt://{{ containers.mqtt.host }}:{{ containers.mqtt.port.mqtt }}

Result: mqtt://mqtt:1883.

  • Implicit depends. A containers.<slug>.* reference makes that container an implicit dependency: it starts first and the referring container waits until it is ready, as with Depends on. The GUIs show it as “implicit (from expression)”. A literal mention such as mqtt://mqtt:1883 or host: "mqtt" only gives a suggestion (“… mentions `mqtt` — add it to Depends on?”, one-click Add) and starts mqtt first, without waiting.
  • One rule. container.* (singular) is always THIS container: container.slug, container.env.<NAME>. containers.<slug>.* (plural) is any container of the site. container.mqtt.host is not a path (E_UNKNOWN_PATH). No container name is reserved.
  • The host is the network alias (= the containerSlug). It resolves from containers on the same site network, whatever the docker name of the container is (the agent option containerNames, see Container driver). From another site, use site.<s>.host and site.<s>.port.<containerSlug>.<portName> (the host port).
  • Allowed in Container.env[].value, image env defaults and file content (a file is one copy per site, and these are facts of the site). Not allowed in mount paths, hosts, port fields or edge fields (E_NOT_ALLOWED).
  • The editors suggest the container names first, then their ports.

Dev-tool presets: use another container's env (§21 #99)

A dev-tool preset that connects to a container usually needs the credentials that container already has. Instead of a second secret, point the preset at the container's env:

username = {{ containers.postgress.env.POSTGRES_USER }}
password = {{ containers.postgress.env.POSTGRES_PASSWORD }}     (the container sets it from the secret pg-password)
database = {{ containers.postgress.env.POSTGRES_DB | default("postgres") }}
  • Where. Only in dev-tool presets (field devtool). Container.env, image defaults, files, mount paths and the edge refuse it (E_NOT_ALLOWED): use container.env.<NAME> for this container, or a variable.
  • Not a literal. Presets never hold a literal password; a container env reference is fine. When the env holds a plain (non-secret) value, the editor shows the warning V_DEVTOOL_PLAIN_ENV (the value is readable in the config). An unknown env name is V_DEVTOOL_ENV, an unknown container V_DEVTOOL_CONTAINER.
  • Editor. Type {{ and pick level by level: containers. → containers.postgress. → env. → the names with their values (secrets masked). With a container target the preset drawer also suggests the well-known names ("Use env POSTGRES_USER of postgress"), and the password has the mode Container env.
  • Agent version. Agents from 0.11.1 resolve it; 0.11.0 refuses such a revision. The cloud warns for each site whose agent is older (it never blocks Publish).

Use the value of one env var in another field

Use container.env.<NAME>. For example, an image has the env var NODE_ENV with the choices integration, dc, worker, pg-listen, terminal and migrate. The volume config must mount the config file of the selected mode. Write the mount path like this:

/app/helper/config/env/{{ container.env.NODE_ENV }}.ts

When a deployment sets NODE_ENV to worker, the agent mounts the volume at /app/helper/config/env/worker.ts. When no value is set, the image default is used.

  • The path must start with /. A relative path such as helper/config/env/{{ container.env.NODE_ENV }}.ts is not valid (V_PATH). The forms show this error next to the field.
  • The agent resolves the env vars first, in dependency order, and then the mount paths. file.<fileSlug>.path gives the resolved mount path of that file.
  • If two values refer to each other (for example A = {{ container.env.B }} and B = {{ container.env.A }}), both get E_CYCLE. The message shows the loop.
  • You can use container.env.* in Container.env[].value, in image env defaults and in mount paths. Not in rendered files: a file is one copy per site, shared by every container.

The playground on this page does not support container.env.*. Use the expression preview in the container editor.

Inside the site network, containers reach each other by the containerSlug (for example http://api:8080, http://api-2:8080). Use site.* only to reach a container on ANOTHER site through its host port.

Worked example: a Mosquitto password file (§21 #103)

Mosquitto (password_file) wants lines user:$7$101$<salt>$<hash>, normally written by mosquitto_passwd. With the filter, the file is generated from a secret, so the broker password and the clients that use it come from ONE place:

  1. Secrets → add mqtt-password and set its value to the plain password.
  2. Files → the password file (here mqtt-pwfile, text, Resolve {{ }} expressions on), mounted read-only by the mosquitto container at the path its mosquitto.conf names (password_file /mosquitto/config/pwfile). Content: 
    northwind:{{ secret.mqtt-password | mosquitto_passwd }}
    One line per user; another user = another secret (ops:{{ secret.mqtt-ops-password | mosquitto_passwd }}).
  3. Dev tools → the MQTT preset: user northwind, password Secret mqtt-password — the same secret, so the preset and the broker never drift apart. Containers that connect use {{ secret.mqtt-password }} in their env too.

The cloud preview shows northwind:•••• (secrets never leave the site). The agent renders the real line once per site at staging and never logs it. File mode: a rendered file with a secret in clear is written 0400, but this one is written 0444, because its secret only reaches it through mosquitto_passwd (a salted hash): Mosquitto opens password_file after dropping to its own user (uid 1883), so a root-owned 0400 file would fail with "Unable to open pwfile". Mosquitto logs a "world readable" warning for it, as it does for a hand-made file today.

Why a deterministic salt. The salt is the first 12 bytes of HMAC-SHA256(key = password, msg = "opm-mosquitto-salt" NUL deploymentId NUL siteSlug). The same password on the same site always gives the same line, so the rendered file — and its hash — do not change at every staging: no file churn in the Diff and no restart of the broker at every apply (a random salt, like mosquitto_passwd uses, would do both). Another site or deployment gets another salt. The tradeoff: two users with the SAME password on the SAME site get identical lines, so anyone who can read the file sees they share a password — give each user its own password. The password is the HMAC key, so the salt itself tells nothing the hash does not.

Compatibility. 12-byte salt + 101 iterations is what Mosquitto 2.0.x writes; the 2.0 broker accepts ONLY 12-byte salts, Mosquitto 2.1.x writes 64-byte salts / 1000 iterations but still accepts 12-byte ones — so the default works with both. Use mosquitto_passwd(6) for Mosquitto 1.x. OPM's hash is checked byte for byte against the real mosquitto_passwd (eclipse-mosquitto 2.0.18 and 2.1) for the same salt, and a real broker accepts the rendered file (agent test TestDockerMosquittoPasswordFile).

Not available on purpose: bcrypt / htpasswd (needs a deterministic-salt bcrypt), hmac (the key would sit in the config), md5 / sha1 (weak). An agent older than 0.13.1 does not know the new filters and refuses the revision; the cloud warns per site on the Diff page and in the publish dialog.

Result typing

  • Each block gives a string: numbers as decimal text, true / false as text.
  • A list or an object must go through join or json. Without it → E_TYPE.
  • A null value without default → E_NULL.
  • Number fields (hostPort, ImagePort.port) must be ONE whole block (spaces around it are allowed). The result must be an integer 1–65535 → else E_TYPE.
  • The final text is used as is. OPM does not add quotes.

Security rules

  • The password-hash filter mosquitto_passwd is allowed only where secrets are (container env, file content, dev-tool presets); elsewhere → E_NOT_ALLOWED at the filter.
  • secret.* is allowed ONLY in Container.env[].value, in rendered file content (written mode 0400 — 0444 when every secret only goes through mosquitto_passwd — mounted read-only) and in dev-tool preset values (resolved on the site, never stored resolved; §21 #97, #99). It is not allowed in hosts, ports, image defaults, mount paths, the edge, or any other field. To give a whole secret to a container, use secretRef or a mount with source secret instead.
  • An env var that gets its value from secretRef or from secret.* is a secret env var. You can use it with container.env.<NAME> only in Container.env[].value and in files. In an image default or a mount path it gives E_NOT_ALLOWED, so a secret never goes into a path.
  • An env value that uses secret.* is a secret value: the agent never writes it to a log or an activity, and the GUIs show ••••.
  • The cloud never resolves secret.*. Its previews always show ••••.
  • The agent reads secret values from its store only when it starts a container or writes a secret volume. They never go to logs.
  • Expressions cannot run code, read the host, or call the network. They only read the paths above.
